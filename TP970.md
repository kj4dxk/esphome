# TempSpike Plus TP970 for ESPHome 2026.11.1

This branch provides the `thermopro_tp970` external component for the stable ESPHome 2026.11.1 builder. Its C++ implementation is identical to the proposed upstream component; only Python code generation uses the older release's API.

```yaml
external_components:
  - source: github://kj4dxk/esphome@tp970-esphome-2026.11
    components: [thermopro_tp970]

esp32_ble_tracker:

ble_client:
  - mac_address: 12:34:56:78:9A:BC # Replace with the booster MAC.
    id: tempspike_client

thermopro_tp970:
  id: tempspike
  ble_client_id: tempspike_client

sensor:
  - platform: thermopro_tp970
    thermopro_tp970_id: tempspike
    internal_temperature:
      name: Probe Internal Temperature
    ambient_temperature:
      name: Probe Ambient Temperature
    battery_level:
      name: Probe Battery
    notification_count:
      name: Probe Temperature Messages

binary_sensor:
  - platform: thermopro_tp970
    thermopro_tp970_id: tempspike
    temperature_stream:
      name: Probe Temperature Stream
```

Add this to an existing ESP32 configuration. Leave active BLE scanning enabled, close the phone app, and undock the probe. This maintains a GATT connection to the booster and consumes one BLE client slot. Shelly advertisement scanners cannot supply that connection.

Only the single-probe TempSpike Plus TP970/TP970R has been tested. Notifications normally arrive about every three seconds; the counter shows continued reception even when temperatures stay unchanged. Invalid fields become unknown independently. Disconnects or 15 seconds without a recognized temperature notification clear the readings; `timeout` is configurable on the hub. Missing traffic is not a definitive docked indication.

The component is not merged into ESPHome. Development review: https://github.com/kj4dxk/esphome/pull/1. Documentation review: https://github.com/kj4dxk/esphome.io/pull/1. The `feat/thermopro-tp970` branch targets current ESPHome dev; this compatibility branch targets the stable builder.
